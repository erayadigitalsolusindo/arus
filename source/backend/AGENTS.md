# AGENTS.md — backend (Go)

> Berlaku untuk `source/backend/`. Aturan global ada di `/AGENTS.md`; desain data di `docs/ARCHITECTURE.md`.

- **Aturan wajib untuk setiap tabel bertenant baru:** kolom `tenant_id` + `ENABLE ROW LEVEL SECURITY` + policy `tenant_isolation` (lihat `00004_rls.sql`) + test isolasi (`platform/db/rls_test.go` sebagai contoh); query lewat `db.WithTenant(ctx, pool, tid, fn)` dengan `tid` dari token; endpoint dipasang `httpx.RequireAuth` → `resolver.Authenticate` → `iam.Require("<modul>", iam.ActXxx)`; modul baru didaftarkan di `internal/iam/permissions.go` (+ `nav.ts` `module`, kamus `iam.module.<id>`).

- **Tata letak modul backend** (tiru untuk modul baru): `internal/<modul>/{service.go, handler.go, queries.sql, *_test.go}` dipecah per use-case bila besar (contoh `auth/`: register, login, recovery, verify, outlet, handler_*). Lapisan bersama: `authz` (izin, `Resolver`, `Authenticate`/`Require`, `Actor`), `audit` (`audit.Record(ctx, tx, audit.FromActor(actor), entry)` **di dalam transaksi perubahan**), `platform/{auth,mailer,background,db,httpx,...}`. Rakitan modul di `cmd/api/modules.go` (`mountModules`).

- **Wajib siap big data (keputusan pengguna 2026-10-09)** — anggap setiap tabel transaksi berisi jutaan baris: daftar/laporan memakai paginasi **keyset** (bukan OFFSET + `count(*) OVER()`), rentang tanggal dibatasi, indeks sesuai filter + urutan (trigram `pg_trgm` untuk `ILIKE '%q%'`), tanpa subquery berkorelasi yang tidak berindeks, ringkasan hanya atas rentang terfilter, pemilih/lookup selalu ber-LIMIT. Query baru yang berat diukur dengan `EXPLAIN ANALYZE` pada data sintetis di tenant uji sementara, dan hasilnya dicatat di log sesi. **Ukur sebagai role aplikasi `aciraba_app`, bukan pemilik:** di bawah RLS Postgres tidak memakai indeks untuk syarat yang operator/fungsinya tidak LEAKPROOF — `ILIKE`/`LIKE` (indeks trigram) dan `lower(col) = …` tidak pernah memakai indeks bagi aplikasi (pemilik melewati RLS sehingga pengukurannya menyesatkan). Pencarian teks yang harus cepat = fungsi `SECURITY DEFINER` yang memfilter `tenant_id = app_tenant_id()` dan hanya mengembalikan id + kunci urut, lalu baris dibaca ulang di bawah RLS (contoh `item_search` di `00051`). Tambahkan juga `CREATE STATISTICS` atas ekspresi teks cari agar perencana tidak salah memilih indeks nama + LIMIT untuk kata yang jarang. Untuk daftar dokumen ber-filter (tanggal/status/keyset/ringkasan): fungsi `*_search_ids` mengembalikan **kandidat id** (maks `db.SearchCap`+1) lalu query daftar/ringkasan biasa memakai `id = ANY(kandidat)` lewat `db.SearchCandidates` (contoh `purchase_search_ids` di `00052`); syarat `kolom_tabel_lain ILIKE` (nama pemasok/member/kasir lewat JOIN) tidak pernah bisa ber-indeks — ubah dulu jadi daftar id pihak lalu `fk = ANY(ids)` pada tabel dokumen agar perencana bisa BitmapOr. Indeks trigram baru selalu ber-tenant: `gin (tenant_id, kolom gin_trgm_ops)` (btree_gin).

## Pelajaran konkurensi & uji (dari log sesi; berlaku untuk semua modul)
- **Baca nilai turunan (HPP, saldo) SETELAH kunci yang benar-benar menyerialkan penulis lain didapat.** Mengunci baris `items` tidak menghalangi penjualan (penjualan hanya mengunci baris saldo): baca stok setelah `stock.ApplyAll`, lalu koreksi dengan qty dokumen.
- **Jangan `FOR UPDATE` pada master yang dirujuk FK anak yang ditulis transaksi lain** (deadlock dengan `FOR KEY SHARE` milik FK); pakai `FOR NO KEY UPDATE`. Kunci beberapa baris selalu terurut (id; `ApplyAll`: outlet, item, bucket).
- Query yang mengunci baris tidak memperbarui hasil JOIN ke tabel lain (EvalPlanQual): baca ulang nilai dengan pernyataan baru setelah kunci didapat.
- Nomor dokumen dari counter di DALAM transaksi dokumen; idempotensi: `ON CONFLICT DO NOTHING` lalu batalkan transaksi (agar nomor tidak bolong). Replay dan akses dokumen per id wajib cek tenant (RLS) dan cabang (`a.OutletID == outlet || a.Outlets[outlet]`; salah = 403 `OUTLET_FORBIDDEN`).
- Perbandingan waktu token (`tokens_valid_after`) memakai jam aplikasi, bukan `now()` DB.
- **Test konkuren harus memeriksa nilai turunan (HPP, saldo berjalan), bukan hanya stok.** Test integrasi di-SKIP bila `TEST_DATABASE_URL`/`TEST_ADMIN_DATABASE_URL`/`TEST_REDIS_URL` tidak di-set (ambil dari `backend/.env`, jangan `source .env`); jangan menyatakan hijau tanpa env itu. Tenant uji butuh `payment_methods` bawaan dan pembersihan tabel anak sebelum `tenants`.
- API dev harus di-restart setelah kode backend/migration berubah. Jangan uji tulis di tenant dev pengguna; pakai tenant sementara lalu hapus.
- Jangan menulis berkas kode dengan PowerShell `Set-Content -Encoding utf8` (BOM merusak non-ASCII); jangan menaruh backtick di dalam string bash berkutip ganda.
